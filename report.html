1. Introduction

Phishing remains one of the most prevalent and damaging cyberattack vectors in the modern digital landscape. According to the Anti-Phishing Working Group (APWG), over 5 million phishing attacks were reported in 2023 alone, targeting individuals, enterprises, and government institutions. Attackers craft deceptive URLs that mimic trusted brands to harvest credentials, financial data, and personal information.

PhishGuard AI is a web-based cybersecurity application that leverages Machine Learning and heuristic analysis to detect phishing threats from URL structure alone. Operating in a strict zero-egress sandbox, the system extracts 18 static lexical and structural features from any submitted URL, feeds them through a trained Random Forest classifier, and produces a calibrated 0–100 risk score with actionable defensive recommendations.

The application is designed for security analysts, students, and everyday users who require an instant, explainable, and privacy-preserving tool to evaluate suspicious links before clicking.

2. Problem Statement

Users frequently receive URLs through emails, chat applications, and social media that appear legitimate but lead to credential-harvesting pages. Existing solutions face the following challenges:

  • Browser extensions require active internet connectivity and third-party blocklist APIs, introducing latency and privacy concerns.
  • Commercial security suites are resource-intensive and inaccessible to students.
  • Many detection tools function as opaque black boxes, offering a binary safe/unsafe verdict without explaining the reasoning.
  • Online scanners submit user URLs to remote servers, violating organizational data policies.
Core Problem: How can a self-contained, offline application provide accurate, explainable phishing threat detection using only URL lexical structure, without making any network requests?

4. Literature Review

4.1 Traditional Phishing Detection Approaches

Early anti-phishing systems relied on blacklist-based detection (e.g., Google Safe Browsing, PhishTank), which maintain constantly updated databases of known malicious URLs. While effective against previously reported threats, these systems suffer from a critical delay between attack deployment and blocklist propagation, typically leaving a 12–48 hour window of vulnerability.

4.2 Machine Learning-Based Detection

AbuAli and Nofl (2019) demonstrated that lexical features such as URL length, presence of IP addresses, and suspicious keywords achieve over 95% detection accuracy using Support Vector Machines. Zhao et al. (2021) showed that ensemble methods (Random Forest, Gradient Boosting) outperform individual classifiers on imbalanced phishing datasets.

4.3 Deep Learning Approaches

Recent works employ CNNs and LSTMs for character-level URL classification (Chawla et al., 2022). While achieving marginal accuracy gains (1–3%), these approaches require GPU hardware and substantial inference time, making them impractical for lightweight, offline deployment.

4.4 Hybrid Scoring Frameworks

Most production systems (e.g., OpenPhish, URLScan) combine rule-based heuristics with ML classification to balance speed and accuracy. PhishGuard AI implements a similar dual-engine architecture in a compact, single-file deployment.

5.2 Design Principles

  • Single-File Architecture: Entire application logic, ML pipeline, and styling resides in app.py for maximum portability and zero-configuration deployment.
  • Stateless Inference: URLs are evaluated independently; no external API calls, DNS resolution, or HTTP requests.
  • Session-Only Persistence: Scan history exists in st.session_state only and is purged on browser close.
  • Cache-Optimized Training: @st.cache_resource ensures the model trains once per cold start and reuses weights across reruns.

8. Machine Learning Pipeline

8.1 Dataset Construction

A curated benchmark dataset of 120 labeled URLs was constructed:

  • 60 legitimate URLs – representing diverse web categories (education, technology, news, government, enterprise)
  • 60 phishing URLs – representing real-world attack patterns (banking portals, fake login pages, brand impersonation, cryptocurrency scams, package delivery fraud, HR credential lures)

8.2 Data Splitting

X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, random_state=42, stratify=y
)
  • Training set: 75% (90 samples)
  • Test set: 25% (30 samples)
  • Stratification: Maintains balanced class distribution in both splits

8.3 Classifier Configuration

HyperparameterValueRationale
n_estimators100Ensemble of 100 decision trees for stable majority voting
max_depth7Limits tree depth to prevent overfitting on small dataset
min_samples_split4Requires minimum 4 samples to split — regularizes against noise
random_state42Deterministic reproducibility across runs

8.4 Model Caching

The @st.cache_resource decorator ensures the Random Forest is trained exactly once per cold application start. All subsequent Streamlit reruns reuse the cached model, reducing repeated computation to ~0 ms.

13.2 Feature Importance Analysis

The top features contributing to classification (by Gini importance):

  1. is_ip – Binary IP detection is the strongest single discriminator
  2. keyword_count – Presence of credential-harvesting terminology
  3. url_length – Excessive URL length correlates with phishing obfuscation
  4. dot_count – Multi-tier subdomain nesting indicates brand impersonation
  5. has_suspicious_tld – TLD abuse rates provide strong prior signal
  6. hyphen_count – Hyphenated domains are a hallmark of typosquatting

13.3 Dual-Engine Agreement

The ML probability and heuristic scores show strong correlation for extreme cases (score < 20 or > 80), while moderate cases (30–60) demonstrate the value of the blended calibration approach, where structural penalties prevent the model from underestimating edge cases.

15. Limitations

  1. Small training dataset: 120 synthetic URLs may not cover all phishing families; real-world datasets contain millions of samples.
  2. Lexical-only analysis: Cannot detect phishing on compromised legitimate domains or dynamic JavaScript-based attacks.
  3. No visual similarity matching: Does not compare rendered page appearance against legitimate brand pages.
  4. No temporal intelligence: Freshly registered domains (strong phishing indicator) cannot be checked without WHOIS/DNS access.
  5. HTTPS is not a silver bullet: The system notes that HTTPS presence does not guarantee legitimacy, but free certificates are increasingly common among attackers.

17. Conclusion

PhishGuard AI demonstrates that effective phishing detection does not require heavy infrastructure, active network connections, or proprietary APIs. By combining 18 carefully engineered lexical features with a lightweight Random Forest ensemble and transparent heuristic rules, the system achieves high classification accuracy while maintaining strict user privacy.

The application's multi-module interface transforms raw ML predictions into actionable security intelligence — providing URL anatomy dissection, batch threat triage, explainable AI decomposition, and defensive recommendations in a polished, production-quality web experience.

As a zero-egress, offline-capable tool, PhishGuard AI is suitable for deployment in air-gapped enterprise environments, academic cybersecurity labs, and resource-constrained settings where third-party scanning APIs are inaccessible or prohibited.
